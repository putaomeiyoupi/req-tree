    二、怎么用（最常用的一条路径）

    resume                                     ← ◎ 开工第一件事：拿回上次现场（RESUME.md）
add --parent R-0006 --title "…" --why "…" --done-when "…"   ← ◎ 发现新问题当场落库
start R-0006                               ← ◎ 开始做（需 done_when；祖先不得已收口）
note R-0006 做到哪 发现了什么                 ← ◎ 做一步记一句（免引号）
bench                                      ← ◎ 随时看手头同时有几件事（BENCH.md）
done R-0006 --note "接口已实现"              ← ◎ 实现完成（≠ 收口）
close R-0006 --evidence "commit:9f2c1ab" --evidence "test:…"   ← ◎ 验证通过才算收口
check                                      ← ◎ 体检（有错返回 1）

    五个完整工作流（首次建真源 / 派生新需求 / 推进与收口 / 出视图与巡检 / 每周巡检）见 skill 内 references/entry-map.md 第五节。

    四、状态定义（6 个）

    状态看板标签含义进入条件
    open未开始已记录，未推进add
    doing进行中正在处理需 done_when；依赖已收口；祖先不得是已收口 / 已放弃（可用 --force 放行，但留 W7 告警）
    blocked阻塞受阻停滞必须给 --reason
    done已完成实现完成，待验证从 doing 转来
    closed已收口已验证收口从 done；≥1 条证据；未被显式接受的未收口后代为 0
    dropped已放弃主动放弃必须给 --reason

    两个关键区分：① done ≠ closed ——「我改完了」不等于「这件事结束了」。 ② 未收口 = open + doing + blocked + done（即除 closed / dropped 外的全部）， 所以统计栏的「未收口」通常大于「未开始」——它们不是同一个数。

    五、筛选口径（数字为什么和直觉不一致）

    项规则
    状态标签默认只显示 未开始 / 进行中 / 阻塞；已完成 / 已收口 / 已放弃默认隐藏 —— 已终结的项混进来会让「还有几件事要做」失真，考古时再逐个点开。点一下 = 切换该状态（不是「只看该状态」）。全关会得到空树，用「重置筛选」一键恢复默认。
    多条件是「且」状态标签 × 「仅未收口」 × 「仅看告警」 × 搜索框，四者同时生效。
    搜索范围只搜 ID / 位置编号 / 标题 / 派生理由 / 收口条件（不含进度记录与收口证据）。
    ⭐ 统计口径默认只统计叶子节点（没有子节点的 = 实际施工项）。需求级容器与根节点的「收口」回答的是另一个问题（「这条线整体达成了吗」），与「还有几件事要做」混在同一个数里会让后者失真 ⇒ 需要看全量时关掉「仅统计叶子」。
    ⭐ 祖先占位为不让树断裂，匹配节点的上层节点会被一并显示——它们本身不符合当前筛选，故用变淡样式标出；统计栏也据此拆成「匹配筛选」与「祖先占位」两个数，而不是一个含糊的合计。

    六、约定与退出码

    项规则
    状态流转open → doing → done → closed；doing ⇄ blocked；任意非终态 → dropped。done（改完了）≠ closed（已验证收口）。
    前置要求start / unblock 需 done_when，且祖先不得已收口 / 已放弃；block / drop 需 --reason；close 需 --evidence。
    两个确认别混用--force 只跳过「未 done 不能收口」的状态检查，跳不过假收口检查；--override-reason 才放行「仍有未收口后代」。两个都踩到时要同时给。
    退出码0 成功 ｜ 1 check/render 发现真源有错 ｜ 2 被强校验或参数校验拒绝。render 在真源有错时不会静默产出空树，别拿错误状态下的视图做判断。
    全局参数--root <真源目录>（写在子命令前后都可以）｜ --no-render 关闭自动刷新 ｜ --wait SEC 写锁等待秒数。
    真源 / 派生物真源：tree.json journal.jsonl baselines.json snapshots/ tree.lock —— 写入只走 CLI。
    派生物：本页等 7 个视图 —— render 覆盖生成，禁止手改。
    结构概览最深（未收口）· 单层最宽 · 最大的一棵树（都带位置编号）见 check ／ resume ／各视图页眉；完整区块在 TREE.md 与本页顶部。层级如实记录需求的派生关系 —— 太深 / 太宽靠定位消化，不靠改造结构：本工具没有改父（reparent）通道。
